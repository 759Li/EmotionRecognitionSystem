# 登录功能说明文档


## 一、功能概述
登录功能是情绪识别系统的用户身份验证入口，用于验证用户身份并授予系统访问权限。通过用户名和密码校验，确认用户合法性后，建立会话（Session）以维持登录状态，允许用户访问系统核心功能（如情绪识别、历史记录查询等）。


## 二、页面结构（login.html）
登录页面提供用户输入界面，核心元素如下：
| 元素          | 类型        | 描述                                                                 |
|---------------|-------------|----------------------------------------------------------------------|
| 标题          | 文本        | 页面顶部显示“人脸情绪识别系统”，明确系统名称                         |
| 登录表单      | `<form>`    | 提交地址为`/login`，请求方法为`POST`                                 |
| 用户名输入框  | `<input>`   | `name="username"`，必填项，占位符为“Username”，绑定用户身份标识       |
| 密码输入框    | `<input>`   | `name="password"`，必填项，占位符为“Password”，用于输入加密验证信息   |
| 登录按钮      | `<input>`   | 类型为“submit”，文本为“登录”，触发表单提交                           |
| 注册链接      | `<a>`       | 文本为“新用户注册”，链接至`/register`路由，支持新用户账号创建         |
| 响应式设计    | CSS样式     | 适配不同屏幕尺寸（max-width:768px和480px时自动调整布局）             |


## 三、交互流程
1. **页面访问**：用户通过访问系统根路径（`/`）或直接访问`/login`路由，加载登录页面。
2. **信息输入**：用户在表单中填写用户名和密码。
3. **提交验证**：点击“登录”按钮后，表单数据以`POST`方式提交至`/login`后端接口。
4. **身份校验**：后端验证用户名和密码合法性，通过后建立会话；失败则返回错误提示。
5. **跳转/反馈**：
   - 验证成功：跳转至情绪识别主页面（`/recognition`）。
   - 验证失败：停留在登录页面，显示错误提示（如“用户名或密码错误”）。


## 四、后端处理逻辑（app.py）
### 1. 请求处理（`/login`路由）
| 请求方法 | 描述                                                                 |
|----------|----------------------------------------------------------------------|
| `GET`    | 返回登录页面（login.html），供用户输入信息                           |
| `POST`   | 处理登录验证：接收用户名和密码，执行校验逻辑，返回处理结果           |


### 2. 核心校验步骤
```python
# 简化逻辑示意
def login():
    if request.method == 'POST':
        # 1. 获取并清洗输入数据
        username = request.form.get('username', '').strip()
        password = request.form.get('password', '').strip()
        
        # 2. 非空验证
        if not username or not password:
            flash('用户名和密码不能为空')
            return render_template('login.html')
        
        # 3. 密码验证（调用数据库管理器）
        try:
            if db_manager.verify_password(username, password):
                # 验证成功：初始化会话
                user = db_manager.get_user_by_username(username)
                session['user_id'] = user['id']  # 存储用户ID
                session['user_info'] = user      # 存储用户基本信息
                flash('登录成功')
                return redirect(url_for('recognition'))  # 跳转至主功能页
            else:
                flash('用户名或密码错误')  # 避免泄露具体错误原因（安全设计）
        except DatabaseError as e:
            logger.error(f"登录失败: {str(e)}")
            flash(f'登录异常: {str(e)}')
    
    # GET请求或验证失败时，返回登录页面
    return render_template('login.html')
```


### 3. 错误处理
| 错误场景                | 处理方式                                                                 |
|-------------------------|--------------------------------------------------------------------------|
| 用户名/密码为空         | 前端通过`required`属性限制提交，后端二次校验，提示“用户名和密码不能为空”   |
| 密码验证失败            | 提示“用户名或密码错误”（不区分“用户名不存在”和“密码错误”，防止信息泄露） |
| 数据库操作异常          | 捕获`DatabaseError`，记录日志（如连接失败），提示“登录异常”               |


## 五、会话管理
登录状态通过`Session`维持，核心机制如下：
- **会话存储**：验证成功后，`session`中存入`user_id`（用户唯一标识）和`user_info`（用户基本信息），用于后续权限校验。
- **权限控制**：系统核心路由（如`/recognition`、`/history`）通过`@login_required`装饰器保护，未登录用户访问时会被重定向至登录页，并提示“请先登录”。
- **会话销毁**：用户主动退出或会话超时后，`session`信息自动清除，需重新登录。


## 六、安全特性
1. **密码加密校验**：通过`db_manager.verify_password`调用BCrypt算法验证密码，避免明文传输和存储。
2. **输入清洗**：对用户名和密码执行`strip()`处理，过滤首尾空格，防止无效输入。
3. **错误信息脱敏**：验证失败时统一提示“用户名或密码错误”，不泄露具体错误原因（如避免攻击者通过提示判断用户名是否存在）。
4. **会话安全性**：`session`基于加密Cookie实现，`secret_key`用于签名保护，防止篡改。


## 七、相关依赖
- **前端**：依赖`style.css`（样式）、`jquery.min.js`（可选交互）、`font-awesome.css`（图标）。
- **后端**：依赖`DatabaseManager`（用户信息查询、密码验证）、`Flask Session`（状态管理）。
- **数据库**：通过`USERS`表存储用户信息（用户名、加密密码等），用于身份校验。


## 八、关联功能
- **注册入口**：登录页面提供“新用户注册”链接，跳转至`/register`路由，支持新用户账号创建。
- **主功能跳转**：登录成功后自动跳转至情绪识别主页面（`/recognition`），开启系统核心功能使用流程。
